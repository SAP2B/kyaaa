# kyaaa 📖✨

**A zero-allocation, zero-stack-overhead heterogeneous container (TypeMap/HList) for `#[no_std]` Rust.**

`kyaaa` provides a way to store, mutate, and iterate over completely different types in a single collection without using `Vec`, `Box`, `dyn Any`, or a single byte of Heap memory.

It is designed for bare-metal, embedded systems, OS development, and high-performance game engines where dynamic allocation is forbidden, but high-level ergonomics are desired.

## 🚀 Key Features

* **Zero Heap Allocation:** 100% `#[no_std]` compatible. No global allocator required.
* **Zero Stack Bloat:** The `Book` struct is `#[repr(transparent)]`, holding only an array of pointers.
* **`.rodata` Type Tracking:** Type validation (`TypeId`) is generated at compile-time and stored statically in the `.rodata` section of your binary.
* **Type-Safe Iterators:** Iterate over specific types using `.list::<T>()` with zero cost.
* **No `vtable` overhead:** Replaces the need for trait objects. LLVM can aggressively inline every operation.

## 🛠️ Quick Start

Define your structs using `kyaaa::page!` (which automatically generates getters, setters, and byte-serialization), and instantiate your heterogeneous collection with `kyaaa::book!`.

```rust
use kyaaa::{page, book};

// 1. Define your data types
page!(
    struct Game {
        name: &'static str,
        favorite: bool,
    }
    struct User {
        name: &'static str,
    }
);

#[test]
fn book_hlist() {
    // 2. Create a heterogeneous collection on the stack/static memory
    let hlist = book!(
        zelda => Game { name: "Zelda", favorite: true },
        nier => Game { name: "Nier Automata", favorite: true },
        lol => Game { name: "League of Legends", favorite: false },
        sap => User { name: "SAP2B" }
    );

    // 3. Zero-allocation Type Iterators!
    assert_eq!(hlist.list::<Game>().count(), 3);
    assert!(hlist.list::<User>().eq([hlist.sap().get()]));
    assert_eq!(hlist.list::<User>().next().unwrap(), hlist.sap().get());

    // 4. Safe runtime type-checking by index
    assert_eq!(hlist.zelda().get(), hlist.get::<Game>(0).unwrap());
    assert_eq!(hlist.nier().get(), hlist.get::<Game>(1).unwrap());
    assert_eq!(hlist.lol().get(), hlist.get::<Game>(2).unwrap());
    assert_eq!(hlist.sap().get(), hlist.get::<User>(3).unwrap());

    // 5. Mutate directly (zero-cost direct memory access)
    hlist.zelda().set().name = "New Zelda";
    hlist.nier().set().name = "New Nier Automata";
    hlist.sap().set().name = "New SAP";

    // Or use closure-based updates
    hlist.lol().update(|mut game| {
        game.name = "cs2";
        game.favorite = true;
        game
    });

    // 6. Verify changes
    assert_eq!(
        hlist.get::<Game>(hlist.zelda().id()).unwrap(),
        hlist.get::<Game>(0).unwrap()
    );
    assert_eq!(hlist.zelda().get().name, "New Zelda");
    assert_eq!(hlist.lol().get().name, "cs2");
    assert!(hlist.lol().get().favorite);
}

```

## 🔬 The Proof: Absolute Zero-Cost Abstraction

Because `kyaaa` maps everything at compile time using static memory and raw pointers, there is no runtime dispatch. To prove it, let's look at the generated assembly.

### The Rust Code

```rust
use kyaaa::{page, book};

page!(
    struct Game {
        name: &'static str,
        favorite: bool,
    }
    struct User {
        name: &'static str,
    }
);

fn main() {
    let hlist = book!(
        zelda => Game { name: "Zelda", favorite: true },
        nier => Game { name: "Nier Automata", favorite: true },
        lol => Game { name: "League of Legends", favorite: false },
        sap => User { name: "SAP2B" }
    );

    // Using the builder pattern generated by page!
    hlist.zelda().set().name("New Zelda");
    hlist.nier().set().name("New Nier Automata");
    hlist.lol().update(|mut game| *game.name("cs2").favorite(true));

    let after_hlist = [hlist.zelda().get(), hlist.nier().get(), hlist.lol().get()];

    black_box(after_hlist);
    black_box(hlist.sap().get());
}

#[inline(always)]
fn black_box<T>(dummy: T) -> T {
    core::hint::black_box(dummy)
}

```

### The Generated Assembly (x86_64)

Notice how the compiler optimizes the entire `hlist` abstraction away. There is no heap allocation (`malloc`), no dynamic dispatch overhead. It compiles directly into raw instruction pointer (`rip`) offsets and direct memory moves:

```asm
.section .text.gameasm::main,"ax",@progbits
    .p2align    4
.type    gameasm::main,@function
gameasm::main:
    .cfi_startproc
    # zelda.name = "New Zelda"
    lea rax, [rip + .Lanon.4c1f75b289a1666d08a8506f20956906.1]
    mov qword ptr [rip + gameasm::main::zelda], rax
    lea rax, [rip + gameasm::main::zelda]
    mov qword ptr [rip + gameasm::main::zelda+8], 9
    
    # nier.name = "New Nier Automata"
    lea rcx, [rip + .Lanon.4c1f75b289a1666d08a8506f20956906.2]
    mov qword ptr [rip + gameasm::main::nier], rcx
    lea rcx, [rip + gameasm::main::nier]
    mov qword ptr [rip + gameasm::main::nier+8], 17
    
    # lol.name = "cs2" | lol.favorite = true
    lea rdx, [rip + .Lanon.4c1f75b289a1666d08a8506f20956906.3]
    mov qword ptr [rip + gameasm::main::lol], rdx
    lea rdx, [rip + gameasm::main::lol]
    mov qword ptr [rip + gameasm::main::lol+8], 3
    mov byte ptr [rip + gameasm::main::lol+16], 1
    
    # Packing for black_box
    mov qword ptr [rsp - 24], rax
    mov qword ptr [rsp - 16], rcx
    mov qword ptr [rsp - 8], rdx
    lea rax, [rsp - 24]
    #APP
    #NO_APP
    
    # Handling sap (User)
    lea rax, [rip + gameasm::main::sap]
    mov qword ptr [rsp - 24], rax
    lea rax, [rsp - 24]
    #APP
    #NO_APP
    ret

```

## How it works under the hood

When you call `book!`, `kyaaa` does a few clever things:

1. Wraps each item in a thread-safe `UnsafeCell` statically.
2. Generates an internal `enum` mapping your identifiers to exact `u8` indices.
3. Builds an array of `TypeId` (`[core::any::TypeId; N]`) that is stored in the `.rodata` segment, ensuring `0` runtime initialization cost and `0` stack bloat.
4. Uses `#[repr(transparent)]` on the main `Book` struct so it acts simply as an array of raw pointers (`[*const (); N]`).

When you call `.list::<Game>()`, `kyaaa` creates a highly-optimizable stack iterator that zips through the raw pointers and the `.rodata` type IDs, filtering only the ones that match, with `O(1)` space complexity.
